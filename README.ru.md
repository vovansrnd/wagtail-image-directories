# wagtail-image-directories

**Добавляет к модели изображений Wagtail год, slug и визуальный навигатор. Новые оригиналы можно хранить в `images/<year>/<slug>/`; при этом сохраняются коллекции Wagtail и пакетные операции с изображениями.**

## Основные возможности

- Просмотр каталогов с количеством файлов, примерным объёмом и пагинацией.
- Пакетная загрузка с ограничениями размера файла, числа файлов и количества пикселей.
- Создание, переименование, объединение, перемещение и удаление групп с проверкой разрешений.
- Отражение структуры каталогов в коллекциях Wagtail.

## Требования и совместимость

- Заявленные зависимости: `Wagtail >= 6.0`.
- Совместимость Python, Django и Wagtail нужно проверять совместно. Нижняя граница зависимости пакета не является подтверждением поддержки каждой версии.

В метаданных пакета заявлен Wagtail >= 6.0, однако нижняя граница зависимости не доказывает совместимость со всеми версиями. В архиве нет полной автоматизированной матрицы Django/Wagtail. Перед обновлением production проверьте точные версии, базу данных, файловое хранилище и настройки развёртывания на тестовом стенде.

## Установка

Установите пакет в то же виртуальное окружение, где работает ваш проект Wagtail:

```bash
pip install wagtail-image-directories
```

Добавьте приложения в указанном порядке, сохранив остальные приложения и зависимости проекта:

```python
INSTALLED_APPS = [
    # Сохраните и остальные зависимости Django/Wagtail, требуемые проекту.
    "wagtail.images",
    "wagtail_image_directories",
]
```

Создайте конкретную модель изображения на основе `AbstractDirectoryImage` и настройте оба параметра модели. Полный пример приведён в английском README.



## Первоначальная настройка

Минимальный пример для начала работы. Замените имена моделей, поля API и URL на соответствующие вашей конфигурации.

```python
# Замените "media" на имя вашего приложения Django.
from django.db import models
from wagtail.images.models import AbstractRendition
from wagtail_image_directories.models import AbstractDirectoryImage

class CustomImage(AbstractDirectoryImage):
    pass

class CustomRendition(AbstractRendition):
    image = models.ForeignKey(CustomImage, on_delete=models.CASCADE, related_name="renditions")
    class Meta:
        unique_together = (("image", "filter_spec", "focal_point_key"),)

WAGTAILIMAGES_IMAGE_MODEL = "media.CustomImage"
WAGTAILIMAGES_RENDITION_MODEL = "media.CustomRendition"
```

Затем создайте и примените миграции для приложения конкретной модели и выполните `python manage.py migrate`. Это меняет путь только новых загрузок и не переносит существующие медиафайлы.

Английский README в этом каталоге является основной справкой и содержит полные таблицы настроек и расширенные примеры. Этот перевод охватывает практическую установку и основные замечания по безопасности; перед изменением расширенных параметров сверьтесь с английской версией.

### Важные замечания

Новые файлы получают путь `images/<year>/<slug>/`; миграция не переносит существующие оригиналы. Плагин не создаёт кропы, поэтому набор rendition-spec нужно ограничивать отдельно с учётом дисковой квоты.

## Безопасность и эксплуатация

- Поддерживайте зависимости в актуальном состоянии. Для пользовательского HTML используйте предусмотренную очистку и вывод; не применяйте безусловный `|safe` к сохранённым комментариям или сообщениям форума.
- Проверьте миграции и разрешения под обычной учётной записью, пользователем с ограниченными правами, модератором и администратором.
- В многосайтовой конфигурации проверьте каждый настроенный домен и неизвестный домен. Если Site не найден, запрос не должен расширяться до записей всех сайтов.
- Считайте API-токены, SMTP-пароли и приватные URL секретами. Не коммитьте их в Git и не вставляйте в публичные отчёты об ошибках.
- Сделайте резервные копии базы и медиа перед миграциями, массовым перемещением файлов, импортом или первой массовой публикацией. Сначала выполните операции на тестовом стенде.
